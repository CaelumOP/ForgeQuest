### Web Architecture Notes

- **Live-workout state & set writes:**
  - All ephemeral session state lives in component hooks inside [LiveWorkoutScreen.tsx:85-117] (`rest`, `hold`, `effortSetId`, `previous`, `harder`, `reasons`, `best`, `editedRepsRef`, `editedWeightRef`, `prBuzzedRef`, `celebratedRef`). Active rest/hold timers also mirror to `sessionStorage` (`fq.live.timers`) via [timers.ts:74-83].
  - Reactive set rows come from Dexie's `liveQuery` via `useSets(sessionId)` ([workouts.ts:490] → [live.ts:6]), mirrored into `setsRef.current` for handlers.
  - Set writes originate from `save` (`:391`), `carryForward` (`:409` → [groups.ts:125]), `toggle` (`:415`), `copyLastSetTo` (`:439`), `useLastTimeForExercise` (`:454`), `stopHold` (`:494`), and direct `onChange` calls from [SetRowView.tsx:115-123,269,277] (including `pickFromChips` for effort tags, which currently bypasses any live-screen effort handler).
  - **Concurrency gap:** writes are currently fire-and-forget (`void updateSet(...)`) with no serialization queue; `toggle` fires `save` and multiple `carryForward` writes concurrently. Porting Android's `liveMutex` will need a small per-session promise queue in `LiveWorkoutScreen` (or `workouts.ts`).

- **Set persistence (Dexie):**
  - Defined in [db.ts:62,77-102] on Dexie v3: `sets: '++id, sessionId, exerciseId'`. A `reading` hook at `db.ts:101` hydrates legacy rows with `{ setType: 'WORKING', autoTicked: false, ...row }`.
  - Low-level write helpers in [db.ts:126-131] (`putSet`, `putSession`, `deleteSet`, stripping `id: 0` via `forInsert` so IndexedDB auto-increments) are wrapped by [workouts.ts]: `startSession` / `addExercise` / `swapExercise` build rows via `buildSetsFor` (`:541`) and insert with `db.sets.bulkAdd`; single edits use `updateSet` (`:593`), `removeSet` (`:594`), `addSet` (`:596`); finished sessions use `finishSession` (`:684`) and `updateFinishedSet` / `deleteFinishedSet` (`:816-826`), which call `recomputeRecords`.

- **Test organization:**
  - Vitest 5 (`npm test` → `vitest run`, [package.json:10,24]; no separate `vitest.config.ts`).
  - Tests are colocated next to source as `*.test.ts` across `web/src/domain/` (e.g., [progression.test.ts]), `web/src/ui/` (e.g., [groups.test.ts], [timers.test.ts] using `vi.useFakeTimers()`, [metrics.test.ts]), and `web/src/data/` ([workouts.test.ts], [backup.test.ts]).
  - Data-layer tests import `'fake-indexeddb/auto'` on line 1 and wipe all Dexie tables in `beforeEach(() => Promise.all(db.tables.map((t) => t.clear())))`.
